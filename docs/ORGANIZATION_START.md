# Your first organization assignment

**An engineer or approved agent can turn selected existing records into a useful draft packet today.** The
toolkit supplies file contracts, generators, checks and examples. Your team supplies interpretation, source
choices, engineering review and continuing ownership. Organization-wide use also needs supported company
identity, access, publication and service operations.

Start here if you have a folder of documents and have never used this repository. Choose one assignment and
return something another engineer can review. The [demo series](DEMO_SERIES.md) shows work products;
the [workflow map](WORKFLOWS.md) owns exact supported formats.

Keep company originals and generated work in approved private locations outside this public checkout.

## What runs, what needs preparation, and who owns it

Here **ready to run** means a supplied example works, or a tool accepts inputs already in its documented
contract. It does not mean an arbitrary company folder is ingested or the output is approved.

| Piece | Ready to use | Active preparation or judgment | Continuing responsibility |
|---|---|---|---|
| First source question | Copy the [plain brief](../examples/first-pilot/pilot-brief.md); use manual review or approved Copilot. No installation. | Select permitted records; check citations; separate facts, interpretation, conflicts and gaps. | Investigator/reviewer returns the contribution to the company record location. |
| Supplied tutorials | Run stated commands with their fixtures and prerequisites. | Read what to substitute. Reproducing an example differs from processing your records. | Technical owner maintains the approved environment and versions. |
| Your maintenance history exports | The [history workflow](MAINTENANCE_HISTORY.md) accepts explicitly mapped assets/orders and optional material/labor CSV/JSON. | Qualify identities, source selection, dates/code meanings and any signed-hours policy; investigate recurring-work candidates. | Records owners resolve unknowns and retain accepted company records; managers decide the next investigation. |
| Your supported DEXPI XML | The [reader](../examples/from-dexpi-xml/README.md) consumes supported 1.x/Proteus XML directly. | Obtain the right export; review omissions and inferred placement. Native 2.x XML/JSON is not supported today. | Engineering/document owners determine applicability and accepted revisions. |
| Your drawing image | [Intake](../examples/own-drawing/README.md) consumes a PNG, compatible extraction and manifest. | Prepare an image if starting with PDF; obtain an approved extraction; review assets/connections. | Engineering review and approved source/model-processing route. |
| Your description | [Prepare/check/build](../examples/from-description/README.md) packages UTF-8 text and builds from a checked authored answer. | Engineer/approved assistant authors model, geometry and quotations. PDF/Word text preparation is separate. | Qualified engineer reviews meaning, omissions and intended use. |
| Your process data | [Analysis](PROCESS_ANALYTICS.md) consumes specified CSV and calculation plans. | Qualify identities, units, clocks, quality, phases and comparable scope. Generic workbooks need preparation. | Process/data owners review basis and conclusions. |

Unknown ownership stays unknown. | Publisher/reviewer/backup checks revisions and disposition. Local refresh sends no notifications. |
| Optional read-only MCP | Technical owner exposes a selected packet through the starter and an approved client. | Approved Python/SDK/client setup. Standard-library readers need no server. | IT/service owner provides company authentication, access, operation and support for shared use. |

Most jobs do not need every row. Check [dependencies](DEPENDENCIES.md) before requesting installation.

## From a typical document folder to the first useful result

**1. State the job and permitted scope.** Explain one equipment issue, clarify a change, or prepare a newcomer
to review one system. Select records and an approved environment. Unknown reviewer/sponsor details can remain
open while preparing a draft from already permitted records; do not invent them to complete the packet.

**2. Inventory actual originals.** Copy the [document index](../examples/first-pilot/document-index.csv) into an
approved private location, or use its columns in an existing company tool. It is a manual worksheet, not an
importer. Record location, ID/revision, authority, availability, intended job, preparation and next role.
A filename in a list is not the original. A later date does not establish supersession.
Record exact pages/sections and an original-byte hash when one has actually been computed or supplied; leave
unavailable hashes unrecorded rather than copying an example's fingerprint.

**3. Choose the minimum route.** Ordinary PDFs, Word files, spreadsheets, manuals and notes can support a
manually reviewed finding. This toolkit does not automatically parse, reconcile and continuously index the
whole folder. For a model, prepare the selected description/image or supported export. For analysis, transform
a permitted export into the exact contract and retain that transformation's basis. Keep unavailable or
unsupported records visible instead of fabricating contents.

**4. Produce a bounded contribution.** Use the [first-question guide](../examples/first-pilot/README.md) by
default. Add a model when relationships, generated views or signal mapping help the job. Correct validation
errors against the original. An instrument list may cross-check a tag without being a compatible mapping CSV
or proving installed identity. A source note without an equipment identity cannot establish its own association.

**5. Hand over evidence and decisions separately.** Return the source index, a qualified finding or unresolved
disposition, relevant draft model/calculation and checks, missing preparation/evidence, and next reviewer/owner
decisions. Mark unaccepted ownership **needs owner**. Conflicting pressure values remain conflicting records
until the responsible authority resolves applicability. Neither a newer number nor a source match is installed truth.

A manual finding saved beside a graph is not automatically included in that graph or an MCP response. Keep the
whole handoff together. To expose the finding through selected structured reads, explicitly author it through
the supported [context-register](CONTEXT_REGISTER.md) or [knowledge-packet](../examples/engineering-onboarding/own-packet/README.md)
route and check the resulting readback. These routes do not automatically import an arbitrary brief.

**6. Establish maintenance before others depend on it.** Name who checks revisions, refreshes outputs, reviews
affected answers and records receipt. Preserve previous sources/history; choose a company home and backup.
The [source-change](../examples/pump-revision/README.md), [structural-change](../examples/engineering-change/README.md)
and [owned-team](../examples/team-context/README.md) tutorials show different parts, without company synchronization.

## Decisions an agent prepares for people

| Decision | Responsible role to identify | Agent contribution |
|---|---|---|
| Outcome, acceptable errors, reviewer capacity and expansion budget | Team lead/sponsor and receiving engineer | Proposed scope, baseline, alternatives and first-result evidence. |
| Governing revision and installed/operating state | Engineering/document authority and operations owner | Exact references, conflicts and requests for independent evidence. |
| Permitted data, assistant, installation and IT/OT route | Data owner and IT/OT owner under company policy | Data-flow/preparation inventory and feasible approved route. |
| Publication, review, revision checks and support | Team/site leadership and actual source/service owners | Responsibility proposal and receiving checklist; role labels do not authenticate acceptance. |
| Shared service or managed-product handoff | Leadership and IT/service owners | Workload, access/freshness needs, support burden and bounded receiving trial. |

One person may combine roles in a small team; departments/sites need explicit boundaries. Leadership need not
approve every script run already authorized by an assignment and policy. It must provide ownership and resources
for continuing shared reliance. See [scaling](SCALING_ENGINEERING_CONTEXT.md) for failure signals and upgrade criteria.

## Copyable assignment for an approved agent

Replace brackets with the actual assignment. This is a work brief, not a permission mechanism.

```text
Use the Industrial Context Toolkit to prepare one reviewable contribution.
Job/recipient: [question, intended use and receiving role].
Permitted records/location: [selected files, source IDs/revisions and boundaries].
Permitted tools/environment: [approved tools and allowed actions].
Known reviewer/owners: [actual roles or needs owner].
Output location and stop/review conditions: [private destination and limits].

Start at README and docs/ORGANIZATION_START.md, then the matching tool contract.
Inventory available originals, missing records and required format preparation.
Choose a document-only finding or the smallest supported model/analysis route.
Use my records; supplied tutorial data is only a format example.
Retain source locations/revisions, interpretations, conflicts and unknowns.
For tool work retain inputs, versions, commands, validation results and failures.
Do not invent facts, authority, approval, owners or measured benefit.
Return the draft, missing evidence/preparation and next human decisions.
Explain explicit refresh and continuing ownership before shared reliance.
Do not infer permission for external processing, installs, company connections
or publication from a tutorial or referenced workflow.
```

The first milestone is a contribution another engineer can reconstruct, with a clear receiving route. The
longer-term vision is reusable company context with maintained identities, evidence, decisions and workflows.
That needs deliberate company operations as well as software. Use the [acceptance exercise](ACCEPTANCE.md)
with real participants to establish usefulness, then the [foundation roadmap](ENGINEERING_FOUNDATION.md)
for what further capabilities unlock.
