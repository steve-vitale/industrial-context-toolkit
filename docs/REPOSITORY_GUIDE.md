# Find the right tool, instructions and evidence

Start with a maintenance or engineering decision in the [README job selector](../README.md#start-wherever-you-are).
An assistant helping with records should follow [AGENT_START_HERE.md](AGENT_START_HERE.md), select one job,
inspect the supplied evidence and return a finding. Reproducing or evaluating the toolkit is a separate route:
use [the executable reproduction guide](REPRODUCE_A_WORKFLOW.md).

## Directory responsibilities

| Location | Role | How to use it |
|---|---|---|
| `scripts/` | Reusable tool entry points, internal helpers, case/research runners and regression checks. | [SCRIPTS.md](SCRIPTS.md) identifies each role. A research runner's dataset assumptions do not define the supported scope of a reusable tool. |
| `docs/` | User workflows, format contracts, readiness, evaluation methods and dated research records. | Use the [documentation map](README.md). The canonical references below keep these roles distinct. |
| `examples/` | Public/fictional tutorials, input fixtures, expected outputs and retained case evidence. | Use the [example entry point](../examples/README.md). Each guide identifies what to substitute and what remains supplied interpretation. A replay uses that example's records. |
| `data/` and `schemas/` | Declared data contracts, public/fictional source records and registries. | Read the selected workflow's schema/profile. Keep company inputs and working outputs in an approved private location. |
| `benchmarks/`, `predictions/`, `extraction/`, `runs/` | Task/key/run metadata, saved predictions, extraction recipes and raw-run retention policy. | Use [benchmarks/README.md](../benchmarks/README.md) and [predictions/README.md](../predictions/README.md). Saved scoring is distinct from making a new model call. |
| `out/` | Committed case-study results and generated demonstration artifacts. | Some are evidence inputs to checks, not disposable build files. Regenerate only through the owning recipe; choose a fresh external folder for your own job. |
| `pipeline/`, `docker/`, `.github/` | Declared demonstration stages, local lab packaging and CI. | These reproduce selected assemblies/checks. They do not configure an arbitrary plant or establish native platform acceptance. |
| `assets/`, `drafts/` | Supporting visuals, visual prototypes/builders and captured review evidence. | The [interactive-tour prototype](../drafts/interactive-tour/README.md) and other draft guides state their scope. Use current tool guides for own-input behavior. LinkedIn publishing/content planning belongs in the separate dedicated repository. |

Existing evidence paths are retained because manifests, source pins and historical replay commands refer to
them. Improve discovery through these entry points rather than moving a hashed fixture without migrating and
checking every dependency. The numbered CAD folders are chronological experiments; their
[qualification index](../examples/cad-handoff/qualification/README.md) owns the current conclusion.

## Communicate the capability at its actual level

Describe a route as **input → supplied preparation → tool → output → receiving check**. For example,
markup review needs the exact original/instructions/return, an annotation inventory and source-bound readings.
The checker compares those records; it does not itself read handwriting. Graph-path review consumes a prepared
graph; it does not infer operating consequences. CAD value-span editing preserves declared source bytes;
the native editor's full-save differences remain failures. Calculation and automation worksheets are manual
methods, not simulator or MTP/PLC adapters.

Keep tools, tutorials and case evidence separate in additions. Register a new tool in the script and feature
registries, connect its contract and example through the workflow map, and add an appropriate job-selector link.
Do not create a second catalog with a competing readiness badge. Link to the owner of a fact instead of copying
fast-changing result counts into every front page.

Use the client's existing CAD/CMMS/SharePoint/approved assistant where it fits the job. Optional MCP serves the
documented selected snapshots; source acquisition, authentication, live monitoring, notifications and accepted
company decisions require their own implementations and evidence. [Connectivity](INTERNAL_CONNECTIVITY.md)
and the [alerts boundary](DELIVERY_ROADMAP.md#alerts-detection-and-maintained-delivery) explain that handoff.
