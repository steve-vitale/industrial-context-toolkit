# An external reader through the reader slot: pid-to-kg on the development sets

Generated by `scripts/external_reader_comparison.py`; do not edit by hand. Development sets only (OPEN100 0-5, TE revisions A and D, Pahala P-401/P-501): every number here was seen while comparing, none is a generalization claim. pid-to-kg is [Scott Duncan's public MIT skill](https://github.com/ScottDuncanAI/PID-to-Knowledge-Graph); it is a measured comparison and a source of ideas here, not a dependency. Its graph.json enters through `scripts/reader_external_kg.py`; the adapter's rules were fixed before any score was seen, and the key converted through it scores perfect (`scripts/test_reader_external_kg.py`). Readings of OPEN100 sheets are CC BY-SA 4.0 derived data (`predictions/README.md`); the Pahala readings are not in this repository, only their counts.

## How it was run, and where that differs from a person using it

- Commit `7ee3a82`, claude-opus-5-5[1m], Claude Code headless (`claude -p`), the skill copied into a fresh project folder per run, Python 3.12 with its requirements (OCR on). Exact prompt, flags and harness hashes: `out/ext_pidkg/runs.json`.
- Three runs per development sheet with the identical recipe; ablations two runs each.
- Not how its README describes a person using it: (1) OPEN100 and TE sheets are PNGs, saved as one-page PDFs at a declared 300 dpi because the skill reads PDFs, so they take its scanned-page route (upscaling, contrast); (2) headless, so nobody answered its questions (it was told to choose and note); (3) Python and packages were installed beforehand, not by the skill; (4) one run per sheet, with each set assembled afterwards by its own builder (no model), so its model never re-checked cross-sheet links; (5) shell access was limited to `python -I` and `ls`, so a few shell calls per run were refused and it worked around them.
- Ablations, each a user-level setting with no change to its code: OCR off = the skill's requirements without rapidocr-onnxruntime (a second venv; numpy is then absent too, so blank-tile detection uses the skill's histogram fallback): no OCR hints, no OCR orientation or text-size render choice; text-layer hints remain on PDFs that have one; QA loop off = prompt adds: Skip the QA loop (step 7 of the checklist): run build_kg.py once, do not re-check or fix any warning, and go straight to the report.; 2x2 tiles = prompt adds: When you render the pages, run render_pages.py with the options `--long-edge 5000 --tile 3000 --overlap 900` (a 2x2 tile grid); otherwise follow the skill as written.

## Decision rule

Review loads differ only when the run ranges do not overlap and the 95% paired sheet-bootstrap interval of the difference excludes 0 (module docstring). Our OPEN100 traced readings are one run each, so their run range is a single value; our validation-set replicates (the leaderboard: claude 27.2-31.6 over five runs on other sheets) show a run spread of a few points.

## Control loops (TE, truth `data/te_control_loops.json`: 11 valve loops and 8 cascades that run)

A valve loop counts when one pid-to-kg loop holds both its sensor tag and its valve tag; a cascade when the loop holding the master's sensor cascades to the loop holding the slave controller.
