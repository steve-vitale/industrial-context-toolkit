# Reader leaderboard

Generated by `scripts/reader_leaderboard.py` from [the registry](registry.json); do not edit by hand. `python scripts/reader_leaderboard.py --check` confirms this page matches the registered results.

**Prototype evidence, not a product ranking.** Today's reader drafts: a general model on drawing tiles plus a code line tracer. Trained models (such as PID2Graph's) and commercial readers very likely read lines better ([PRIOR_ART.md](../docs/PRIOR_ART.md)); none has been registered here yet. To add one, follow [PLUG_IN_A_READER.md](../docs/PLUG_IN_A_READER.md).

How to read it:

- A row is one reader: model identifier (contributor-declared, not provider-attested), method with its recipe, and interface. Runs × cases counts replicate runs and the sheets each run attempted.
- Uncertainty is mean ± standard deviation (min–max) over replicate runs on the same fixed sheets. It is run-to-run spread, not a significance test, and says nothing about other drawings.
- Review load counts corrections (false, missed and relabelled symbols, false and missed links) per 100 key items. It is recomputed from the committed predictions with the frozen scorer; it is not measured reviewer time.
- A rank orders the means inside one table; it is not a significance test. With a handful of sheets, sheet-to-sheet variation is far larger than run-to-run spread. For example, the round-5 GPT and Claude methods on OPEN100 sheets 6-11 differ beyond run noise but tie across drawings under a sheet bootstrap ([EVALUATION.md §4a](../docs/EVALUATION.md#4a-later-rounds-at-a-glance)).
- Every table carries its controls scored on the same keys: a reader that cannot clearly beat the deliberately wrong answers has not shown anything.
- Only rows inside one table are comparable. Different families, splits, cases or scorer contracts are different tables, and a number from one is never ranked against another.

## Held-out

*Sealed until a frozen method was scored once. The only level that supports a generalization claim, and then only for the family it covers.*

No reader result is registered on a held-out split yet. Older one-time held-out scorecards (round 2, PID2Graph holdout B, `out/scorecard_hb-*.md`) are not registered here: their keys are downloaded, not committed, so they cannot be re-scored offline. A first sealed held-out result for any reader is the most useful next addition.
