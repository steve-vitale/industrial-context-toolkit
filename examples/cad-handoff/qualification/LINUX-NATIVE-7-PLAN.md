## Development evidence and required observations

1. Start with the exposed fictional valve and its exact original hash/plan. It is development evidence, not a
   held-out case. Original source and all earlier native results remain unchanged.
2. Show the actual native GUI and visible drawing. Interact with native menus/property controls through GUI
   events, not the QCAD entity-edit/export API. Retain before/after screen images and action/observation records.
3. Change existing MODEL/SERIAL/SIZE using native UI controls; inspect unchanged ICT_ID and foreign attribute.
   Save to a new returned DXF using the native Save As dialog, close the document and reopen that saved file.
   Observe stored values in native UI and independently inspect the exact returned file. Record default format.
4. Run the unchanged strict comparator and receiving review on original/return with the supplied plan. Retain
   every difference. A successful UI action is not a strict preservation pass or a reason to waive earlier rows.
5. Inspect model geometry and each affected/unchanged label at useful zooms on source/candidate under identical
   display settings. Use ordinary native GUI views rather than modifying/removing any printed trial watermark.
   Record fonts, clipping/overlap/unsupported glyphs and original typography limitations. A successful screenshot
   is only visibility evidence, not general semantic or engineering equivalence.
6. If the desktop works, extend the same predeclared observation recipe to all applicable existing authored/public
   profile categories, including the known paper-layout failure. Keep exposed status and report omitted/failed
   cases. Any corrected preparation/import/preservation method requires its own freeze and fresh validation;
   do not improve a method on these outputs and call them held out.
7. This experiment may close a native editability/visual evidence gap or yield an actual incompatibility. It does
   not complete the entire goal unless source preservation, returned-file comparisons, reserved validation and
   revision/conflict controls are all established for the selected end-to-end route. Sidecar success is separate.
