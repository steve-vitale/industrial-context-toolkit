# Replacement validation and public adaptation plan

Declared before opening replacement public contents or candidate results. The first attempt and exact methods
remain in `round-1/` and `history/method-1/`. Its R12 inspector failure and mixed-brace plain-text harness error
are development evidence. All eight first fixtures are exposed; the original valve is also development.

The revised inspector exports loaded pre-R2000 entity records to an R2000 *inspection* tag projection rather
than crashing or dropping virtual block records. This does not upgrade source bytes. The `compare()` function,
its exclusions/tolerances, the value patcher and independent byte reconstruction remain unchanged. Development
controls include retained virtual records and planted geometry/layer/style/foreign-attribute/XDATA/block losses.
The native harness compares stored attribute text separately from formatted plain text. Native full-save
differences remain strict failures and are not merged into the candidate.

Freeze all revised methods, tests, helpers and the two replacement manifests in `METHOD-FREEZE-2.json`, committed
before runs. Replacement authored sources were committed at d79e437 before the inspector correction; their
generator is procedural, same-author evidence. The six public originals were selected by filename/category
at the same commit, with raw hashes and upstream provenance. They are one ezdxf family, not six plant trials.

Public input preparation is a separate frozen method, `adapt_public.py`:

1. Keep all six selected cases. Copy each exact original and record its unchanged-profile admission/refusal.
2. Refuse unsupported/malformed input, duplicate attributes, empty retained identity/tag, duplicate identity,
   reserved authored-layer/block collisions or no unused editable field. Keep every failure in the manifest.
3. For every model-space INSERT preserve all existing attributes. Add only absent ICT_ID/TAG as clearly authored
   test identifiers. Choose the first unused field in MANUFACTURER, MODEL, SERIAL, SIZE order, set QUAL-BEFORE,
   and plan QUAL-AFTER. No existing equipment value is overwritten to create a convenient fixture.
4. With no INSERT, add one explicitly authored circle/block anchor. Add a named test layer and visible annotation.
   Add attributes at declared fixed offsets. These are test fixtures, not extracted/installed asset identities.
5. Library-save the derived source, retain its exact bytes/hash, additions report and edit plan. This adaptation
   itself is not byte-preserving from the public original. Candidate preservation begins at the derived source.
6. Before candidate execution, commit a separate adaptation receipt binding the original method freeze and exact
   derived manifest. The runner requires both bindings and checks source/plan hashes. It retains failed admission
   rows and returns failure if any selected case fails; no favorable-case selection.

Run matched library and value-span routes on the six authored and six public cases. For every candidate, require
strict zero and independent exact source-plus-plan byte reconstruction. Then native default/R15 edits and a fresh
process readback, same-settings full/detail renders, and the original protocol's UI, revision and planted-loss
gates remain required. API readback never fills the actual UI gate. No acceptance rule is loosened after results.
