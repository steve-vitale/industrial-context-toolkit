# First full-procedure development method

Freeze implementation and prepared case/job bytes before execution. This is
exposed development on the declared prior cases, not the final reserved-method
freeze. The original protocol/PLAN gates remain in force. This first implementation
adds multiple-asset fields, accessible Unicode entry and complete model-view
capture; paper-view receiving and final complete validation are still to follow.

Use the pinned QCAD 3.33.1 / Qt 5.14.2 image and inherited isolated launcher,
configuration, font substitution and event-driven observation transport. Restore
the same initial configuration for every process. All document operations use
native UI controls. Observe actual Qt child identity, exact filename and complete
asset/attribute inventory. The payload adds native attribute IDs to the existing
read-only observations, so selection must equal the chosen INSERT and its actual
attribute children. Clear selection before each asset, select its exact handle,
and verify all fields, including foreign ones. Any ambiguity refuses.

File/handle typing keeps the observed bounded ASCII X11 recipe. Value changes use
one AT-SPI EditableText.setTextContents call on the observed native text control,
with an exact before-value guard, focus/click/Property Editor window checks,
actual return value, bounded exact text observation, then Tab. This installed
capability has not yet been observed for this method; a refusal is a failed
development attempt, not permission to silently use an entity API. Verify the
post-commit native values of every asset and unchanged field before saving.

Each baseline/edited process opens source, verifies every asset and captures the
source. Edited additionally performs every planned field change. Save As requires
the observed R27 format and a new output, followed by document close/reopen,
all-asset field/readback checks, returned captures, document close, seal and normal
application close. A fresh receiver opens original, no-edit return, edited return
and source-preserving candidate serially and repeats all checks. Full-save losses
remain failures in the unchanged offline comparator.

Before native execution, compute fixed common world frames from source/candidate
library bounding-box unions: complete model overview, each asset and each asset's
labels. Padding is max(2 units, 20% of larger span). Apply the already tested
absolute camera formula. Move the pointer outside the application and retain full
desktop/canvas images until two consecutive decoded canvases agree, maximum ten
attempts. Require exact view/size/camera equality before pixel comparison. Planned
label regions come only from native source/candidate bounds for each changed
asset/tag, rounded outward plus two pixels. Compare source/no-edit with no allowed
region and source/candidate plus no-edit/edited with those fixed regions. No
outcome-dependent tolerance, registration, mask expansion or dropped differences.
Images and actual label/geometry observations still need explicit visual review.

Retain failed inputs/actions/processes separately from any later cleanup. No
native restart follows an observation timeout. Complete receiving must bind every
client/native observation, selected asset, value edit, returned file, image,
source/method/configuration and process outcome. The original revision/conflict,
planted-loss, paper/readability and fresh reserved gates remain unfinished.
