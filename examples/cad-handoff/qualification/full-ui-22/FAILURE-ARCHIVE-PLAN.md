# Separate bounded failure record

Freeze this before packaging or auditing the failed receiving attempt. Retain its
whole original directory, original host execution and separately frozen cleanup,
including both pre-cleanup and terminal private-mailbox copies. The native console
exceeds the normal packet's 16 MiB member limit. Use a **separate failed-attempt
format**, at most 32 MiB per member, 192 MiB total and 16,000 regular files, with
an exact SHA-256 inventory, lossless xz archive and safe bounded in-memory readback.
These limits do not change the normal receiving packager or its acceptance.

Check unchanged original method/input pins and actual failed host/controller and
same-container terminal outcomes. Audit the first 4096 calls with the original
transport auditor on an explicitly named prefix view (omit only the final event,
error and final console start/end from that temporary view). This is a prefix
audit, never a normal full-attempt receipt. Independently check the actual final
4097 call, original null-ID result, absent predecessor hash, exact native wire,
native parent/owner, error/staging bytes and actual helper exit. Bind the pending
request, client failure, absent seal/result, missing views and acknowledged cleanup.
Keep all full original bytes in the archive; a prefix view does not replace them.

Publish counts of idle, request and publish invocations from the actual events.
Verify the receiver rejects changed final input/error, hidden failure status and
an invented completion. No pixel comparison or CAD qualification follows from a
successfully retained failure. In-flight independent attempts retain their own
outcomes under the same rules; no automatic restart or inferred result.
