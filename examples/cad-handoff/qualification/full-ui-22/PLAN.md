# Complete native CAD procedure: development before fresh validation

2026-11-08. N119 continues the original [qualification protocol](../PROTOCOL.md).
N118's [event-driven transport](../observer-transport-21/README.md) is a prerequisite,
not the qualification result. Freeze this plan before implementation. No new
reserved case has been selected, generated, opened or tested for this method.

## Keep the original question and routes

Qualify a declared record-framed text-DXF equipment-data exchange, with explicit
ICT_ID/TAG and single-line attribute values, in the recorded QCAD/version/display
environment. Distinguish source-preserving candidate, matched library save,
no-edit native save and edited native save. Preserve the original strict
comparator, value-span patcher, byte checker and all earlier failed evidence.
Any broader native-save loss stays a failed route, even if the candidate passes.
Do not turn zero differences in one route into general CAD or DWG acceptance.

## Develop the complete executable method on declared exposed inputs

1. Reuse the exposed air/water and template cases, then explicitly authored
   development fixtures with multiple identified assets, a foreign attribute,
   non-ASCII text, literal braces/backslashes and pre-UTF8/UTF8 serialization.
   Declare generators, source versions, encodings, line endings, transformations,
   expected values and unfamiliar retained payloads before execution. Development
   fixtures and any failed successor are never relabeled reserved validation.
2. Combine the immutable recorder, absolute camera and serial event-driven
   observer. Keep original evidence and methods intact. Freeze every actual staged
   input, source/method/configuration hash and expected field/frame before launch.
   Preserve exact run/wire/history binding, seal/stop and actual process outcomes.
3. Generalize the job contract explicitly to a list of identified assets. Observe
   every source attribute, including non-target/foreign values. Select each unique
   source handle through the UI; in a return, require an exact unique ICT_ID and
   record the remapped handle. Refuse duplicates/missing identity or ambiguous
   controls. Never use a first matching asset or infer a tag correspondence.
4. Exercise actual native controls for open, selection, field changes, Save As,
   close/reopen and fresh-process receiving. Before mutation, require the exact
   active drawing, selected asset, before value and currently observed field.
   Retain focus, command result, exact completion and post-commit native/UI values
   for every asset and attribute. The observer remains read-only apart from its
   already declared view operation; no document-API editing or saving fills a UI
   action. If accessible Unicode text entry is used, first observe that actual
   native control operation, output and commit; do not assume the binding exists
   or extend the old ASCII-only X11 recipe by assertion.
5. Run separate matched no-edit and edited native processes, then a fresh receiver
   that opens original, both native returns and exact-span candidate. Retain all
   returned bytes, fields/editability, UI actions, complete observations and
   terminal outcomes. Stop dependent work after any failure. Inspect/clean up the
   same process separately; no deadline-based restart or promotion of recovery.
6. Freeze the full camera/frame/mask recipe before comparison. Use common absolute
   frames, pointer-neutral stable captures and exact camera/viewport equality.
   Keep every pixel difference and unchanged geometry/label finding; no tolerance,
   registration, outcome-dependent mask expansion or ignored paper/font failure.
   Inspect actual rendered images and label coverage, retaining the specific
   views and findings. This is agent visual review, not operator/engineering
   readability approval or original-font fidelity.
7. Exercise a second source revision and concurrent manual change. Stale hashes
   and before values must refuse; conflicts remain explicit. Any context/sidecar
   keeps original and candidate sources and never overwrites installed authority.
   Repeat the original planted geometry/layer/style/foreign/XDATA/literal/output
   collision controls with matched baselines. An unsupported representation must
   refuse under its declared rule, not become an unreported dropped case.

## Freeze, then admit fresh cases

Only after the complete development procedure and receiving controls work, freeze
the executable method and its acceptance/key/generation/selection recipes. Then
select fresh reserved public paths and hash originals before candidate execution;
retain upstream revision/license and actual prior exposure. A file needing authored
identity/layout adaptation is labeled as such and its derived source is frozen
separately. Use multiple public geometry categories and source projects; variants
of one drawing are not independent plants. New authored reserved cases provide
procedural boundary checks, not an independent human key or plant evidence.

Run all selected cases beside matched baselines, publish every attempt and retain
failed/unavailable results. A case used to change the method becomes development;
a subsequent transfer claim needs freshly reserved cases. Receive complete packets
offline and challenge missing/changed sources, methods, observations, images,
fields, revisions and process records after recomputing archive inventories.

Report each route/gate separately. Candidate preservation, native editability,
display, revision handling and native full-save behavior are distinct conclusions.
CI must reproduce the offline evidence without commercial downloads/model calls.
Human/site usefulness, installed identity and company/engineering acceptance remain
outside this software qualification. The active goal stays open until the full
declared exchange route has evidence; this plan alone completes no gate.
