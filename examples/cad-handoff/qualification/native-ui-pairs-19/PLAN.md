## Native method to develop and freeze

Use the unchanged pinned Linux QCAD Professional trial 3.33.1 Qt5 image and selected settings input from layout17.
No diagnostic constructor presets, paint forwarding, native entity/property setters, native export API, or hidden
trial restriction changes. Source/library/configuration identities stay bound. No plant data or network.

Actual file opening, entity selection, property entry, Save As, document close/reopen and normal application exit
use native dialogs, accessibility controls or X11 events. The documented By Handle action (TH) offers a selection
method based on an original source handle, rather than drawing-specific pixel clicks. Validate the selected
native ICT_ID/TAG/before value before changing anything; a remapped/wrong handle must stop rather than edit another
object. Retain the exact observed format/filter. Use the same selected Save As format in each baseline/edit pair;
if the planned format is unavailable or a dialog is unexpected, retain the failed observation.

A separately frozen helper may observe current filename/attributes and set a declared common camera only.
It must not import/select/edit/save/export/close documents, accept dialogs or supply values to a property editor.
UI receipt collection is not native CAD entity editing. UI-only startup/dialog capability probes may precede the
full method freeze, but must be labeled preflight and must not open drawings or save an empty file.

For each source run a fresh baseline process (open source, inspect, Save As without an entity edit, document
close/reopen and inspect) and a fresh edited process (open the same source, inspect, edit only MANUFACTURER,
Save As, document close/reopen and inspect). Then use a fresh receiving process to open the original, no-edit
return, edited return and exact-span candidate serially. Retain displayed native fields, enabled/editable state,
view/camera metadata and pointer-neutral screenshots; never infer editability merely from rendering.

All source/candidate/return views for a case use common frozen frames/settings and canvas size. Keep full images
and every changed pixel; report geometry/unchanged-label differences without enlarging a mask after seeing them.
Source and return filenames/bytes must match receipts. Native field values and DXF readback must both match the
declared plan. All full-save strict differences remain failures, even if no-edit and edited returns share them.

## Receiving and progression

Record actual process IDs/commands/exits, selected settings before/after hashes, UI trees/actions/frames, native
returned files and source/candidate hashes. A timeout stops automation but is not proof the app terminated and
does not authorize a restart. Inspect the same live handle. Unknown dialogs, wrong identity, failed edit/save,
ambiguous controls, source overwrite or output collision must stop and remain failures. Corrections on these
exposed cases need a separate pre-execution method snapshot; never relabel an earlier failed attempt.

Compare source to every return with the unchanged strict comparison, retain matched no-edit/edit comparisons
and explicit source-preserving results. No-edit differences can locate serialization effects, not waive them.
Track all source hashes before/after. Supply a bounded lossless evidence packet, offline replay and planted
receiving-loss controls; keep screenshots as observations requiring inspection, not automatic acceptance.

After a repeatable procedure exists, freeze a complete acceptance method before selecting/admitting new reserved
public or independently authored drawings. That future run must include matched baselines, loss controls,
readable/editable views, native returned-file and revision/conflict checks. This development plan consumes no
new validation, changes no original criterion and cannot itself complete the full CAD qualification goal.
