# Native font and complete-frame development controls

Declared before execution. Develop only on the already exposed `validation-cp1251`,
`validation-long` and `validation-unicode` source/candidate pairs from Linux run 7.
Keep every original drawing, strict comparator, patcher, source/plan and old result.
This is not fresh validation or an original-typography fidelity claim.

Compare two otherwise matched fresh Linux native processes, in order: publisher
default font behavior, then process-local `-font-substitution Standard "DejaVu Sans"`.
Use the same pinned image as runs 7/8 and the same locally copied terminal run-7
configuration in both. No font installation, license/clock/mark alteration or file save.
Record the actual font file hashes and resolved family; distribute no font binaries.

Primary versioned source supports this option:
[autostart.js](https://github.com/qcad/qcad/blob/v3.33.1.0/scripts/autostart.js),
[RFontList.cpp](https://github.com/qcad/qcad/blob/v3.33.1.0/src/core/RFontList.cpp) and
[RTextRenderer.cpp](https://github.com/qcad/qcad/blob/v3.33.1.0/src/core/RTextRenderer.cpp).
The annotated tag resolves to source commit `897079c2d11aaa0869f839a6cf5df8a937dbddbe`.
Prior Windows Standard-to-Arial substitution was already tried. This experiment tests
actual Linux native canvas views and fixes framing after substitution; it is not a
claim to have invented substitution or to preserve the source's intended typography.

For each pair and each of its six total asset identities:

1. Read both files with the native reader **after the process font profile is set**.
   Retain every attribute's exact native text, parent, native font and bounds, and
   the parent INSERT bounds. Group by explicit ICT_ID, not attribute order or tag.
2. Union source/candidate bounds per asset, add 20% of the greater dimension on each
   side (minimum two units), and use that same frame for both native document views.
   Do not reuse bounds measured before substitution or zoom source/candidate independently.
3. Native GUI startup uses `-exec` for a view-only request listener. Its API may read
   drawings, activate documents and set the camera. It must never change entities or
   save/export a drawing. This is a rendering observation, not a new UI editability run.
   The actual edit/save/close/reopen evidence from run 7 remains separately scoped.
4. Use Xvfb 2400x1400, observed main-window geometry 1960x1320, with the native property
   editor beside it. Retain trial panels. Retain full unedited native X11 screenshots
   and all frames until two consecutive decoded image-data frames match. Clear preview
   and traverse empty canvas before moving outside, retaining the commands and receipts.
5. Record the native camera and projected text/INSERT corners. Report containment and
   inspect every view for missing glyphs, overlap, clipping and sufficient readable size.
   Font availability or a correct property string alone does not prove canvas readability.
   Retain unsupported glyph-probe API calls as unsupported, never as a glyph pass.
6. Run both profiles on all selected assets and both roles. Stop/retain any failing
   request, then declare any correction before another run. Verify exact input hashes
   before/after and normal native Quit. Do not restart a live/uncertain process.

The known five paper-layout failures are not repaired by a font mapping. They stay
failed. A later general preparation method, pointer-neutral receiver profile and
fresh reserved native validation need separate freezes. This experiment may establish
a useful display method; it cannot finish whole CAD or company/engineering acceptance.
