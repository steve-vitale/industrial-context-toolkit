# Development review interface acceptance

Written before the review-interface implementation. The existing frozen records,
EXPECTED.json and contribution quotes remain the source oracle. This is development,
not a frozen-method transfer or evidence of human benefit.

The delivered offline HTML must let an engineer choose a fully scoped item, inspect
the three component drafts, see conflicting/inactive/unknown information and original
source revisions, and download a proposed text edit without writing JSON. Applying
that download through the CLI must retain the source facts and prior edits, reject a
different packet/revision or changed dependencies, and reopen in a fresh process.

On desktop and at 390px, actually search for the duplicate P-101 tag, choose U1,
inspect the source-bound flow alternatives and missing operating limits, switch to
the controller outline, inspect the recorded FT/FV links, create a rationale-bearing
proposal, download it, apply it and reopen the resulting packet. Repeat after a
source revision; a stale download must refuse rather than silently rebase. Keep the
downloaded bytes and actual browser observations. All controls must remain reachable
without horizontal page overflow. Source text is untrusted text, not executable HTML.

This interface does not establish an engineering release, authenticated approval,
source filtering/access controls or governed-service receiving. A selected draft is not
a safe-to-share source package. Test claims about those independently.
