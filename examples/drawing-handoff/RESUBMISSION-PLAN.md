# Receiving a resubmitted drawing job

Extend the existing receiving command with an optional previous packet. Use the
same supplied-input checkers. Define these requirements before implementation:

- Reproduce the previous packet's findings from its retained portable inputs and
  verify its complete file inventory before relying on its brief. Preserve both
  packets and their source evidence; refuse a changed or inconsistent packet.
- Match drawings by supplied ID, never by their order. Compare request outcomes,
  collateral/coverage facts and CAD field/identity/preservation findings.
- Compare only under the same original and instruction/plan scope. Changes to
  original bytes, original readings, request inventory or CAD plan must remain
  explicit changes of basis, not corrections to the earlier finding.
- A missing drawing/check/finding must not silently close an earlier issue.
  Establish a returned-to-original observation from current source-bound facts
  or unchanged CAD field evidence; otherwise retain an unresolved follow-up.
- Keep safety review, illegibility, baseline mismatch, unknown material and the
  separate CAD preservation failure visible after the fictional correction.
  Current support never establishes engineering closure or a receiving decision.
- Generate a readable revision table and full previous/current evidence. The
  portable output job must reproduce the complete revision brief without the
  original external folders. Jobs without a previous packet keep their behavior.

Validate the existing initial/corrected fictional returns with the previously
authored acceptance key; reorder drawings; omit one; change the request scope;
remove an observation; alter/re-pin a previous brief; replay portably; and run a
markup-only resubmission without optional packages. These checks establish
revision bookkeeping, not new reader accuracy, site acceptance or full CAD
qualification. No new native session is part of this change.
