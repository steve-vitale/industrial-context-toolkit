# Build and use a sourced engineering map

2026-11-09. Scope follows Steve's correction: engineering context, not a
planner-readiness cycle or managed work. The existing local graph/context tools
remain the receiving route; no ChangePilot or CMMS adapter is claimed.

## Question and method

For a selected item, what does the supplied map say, what records support it,
which relationships and disagreements surround it, and what changed in the next
snapshot? Reuse `ontology.ask`, `one_map.problems` and `map_changes.changes`.
Add a portable, offline, read-only explorer rather than another graph schema,
reader, service, workflow engine or feature catalog. Show complete source/review
metadata, original directed edges and conflict/ruling history. A document mention
is a mention; a map edge is not an operating instruction or proof of adjacency.

The explorer accepts a valid `twin-graph-2` snapshot and optional previous snapshot
of the same site. Optional explicit source roots permit retaining referenced
originals only when the map supplies a matching raw-byte SHA-256. Report missing,
unbound and mismatched evidence without silently substituting another file.
Retain exact snapshots and all their fields. The whole selected map is exported;
an item selection is navigation, not an access-control filter.

## Acceptance and matched baseline

`ACCEPTANCE.json` fixes the cases before implementation. Development uses the
already exposed Riverbend fixture, including two distinct P-101s, sourced flow
disagreement, document references and uncertain references. The ordinary-folder
baseline inventories the same exact files and records the same questions; it
does not pretend to answer them or measure a person's search time. Compare the
explorer's actual records with the existing snapshot, source bytes and separate
key, not only item counts or a successful exit.

Before transfer, commit a freeze of tool, renderer, tests, acceptance and replay.
Then run the preselected existing pasteurizer C-to-D snapshots and public
OPEN100 sheet-0 map through the unchanged method. These are author-known
procedural transfers, not blind drawings or unfamiliar-input accuracy tests.
The public route consumes a committed model reading, not the original image;
preserve its source attribution, development exposure and reading limitations.
Do not invent new public plant facts to make a demonstration richer.

## Verification and receiving

Use real separate-process CLIs. Check ambiguous selection before writing,
snapshot schema/site mismatch, typed fields, source mismatch/missing/unbound,
unsafe paths, HTML escaping, duplicate output refusal, exact retained snapshots,
complete selected records, both conflict sides/history, and same-tag separation.
Verify the complete portable package in another directory using only its retained
files. Recompute derived inspection/question/change views through the existing
tools and refuse lossy or altered packages. Inspect the actual desktop/mobile
HTML, navigation and revision selection. No human usefulness or engineering
acceptance follows from author-run tests.

Update the existing one-map feature/script entries and engineer/agent routes.
Run affected regressions, clean-folder replay and exact-final-head CI, then the
authorized PR/merge process. Preserve historical methods, frozen foundation/CAD
files and every negative result. No job readiness, tasks, reminders, approvals,
operating instructions, live connectors or managed source-of-truth service.
