# One foundation, a receiving handoff and the next change

Opened 2026-11-09 after the source-qualified history workflow. This is a bounded
software/portability job, not an organizational SSOT deployment. Preserve the
existing CAD and reserved-public-data failures.

## Useful manager job and receiving route

An engineer assembles the evidence for work on one fictional unit: selected asset
history, a consultant drawing-return finding and a source note. Keep another
unit's equal-looking asset tag distinct. Return what can be reconstructed, what
needs review, who owns the relevant record and what to revisit on the next export.

Use current contracts rather than a universal new engineering schema:

- `maintenance-history-result-1` and its exact retained originals/receipt.
- The current drawing-receiving/markup result and its retained source records.
- An explicitly authored Native model and reviewed-declaration identity crosswalk.
- `twin-graph-1`, `context-register-1` and, where useful, `engineering-onboarding-1`.
- The existing snapshot readers as the actual software receiving target.

Inspect code before selecting the narrow projection. The receiver must read back
every relevant represented field, source qualification, relationship and history,
not only return matching item counts. If a receiver represents a record only as
retained source content, say so. Keep complete originals beside projections and
report unsupported fields/roles. Do not describe archived JSON as native operational
graph ingestion or as an implemented governed-service import. A later product adapter
needs inspection of that product's actual contract and its own receiving checks.

## Acceptance, comparison and exposure

Commit this plan, the separate expected-behavior key and a simple file-inventory
baseline before implementation. Development may reuse the exposed fictional
maintenance history and markup tutorials. Their identities and facts are teaching
data. Public-source acquisition and extraction are separate from this handoff.

Before opening reserved records, freeze code, mappings, fixtures already seen,
receiving contracts, validator and scoring rules. Preselect a second authored
case with a different asset namespace/export layout and changed/missing sources;
keep its fixed key separate from adaptation. Report author exposure honestly:
procedural reservation is not independent human/plant validation. Do not change
the criterion, replace a failed case or tune to its outcome under the same freeze.

Run actual producer CLIs, receiving reads and full export/reopen in separate
processes with new directories. Include deliberate wrong identities, missing
history, changed types, replaced sources and authority inflation. Keep all
refusals and any failures before fixes. No model/CAD session or company access is
required. Fresh-agent work requires authorization under the session's agent rules;
an author-run process rehearsal must be labeled as such.

## Revision and conflict cycle

Keep immutable original/previous evidence. Receive a changed work-order export
and a corrected drawing/source revision. Reopen dependent findings while leaving
an independently sourced answer current. Retain both conflicting proposals from
one base, with no silent last-writer acceptance. Reject stale bases and repeated
deliveries that would duplicate history. Omitted records remain unresolved
omissions. A new accepted version requires an explicit receiving decision through
the company's own system; fixture role/review names grant no authority.
